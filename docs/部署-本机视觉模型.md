# 本机视觉模型部署记录（v2.20 任务 5）

> 用户决策：**本地为主力，云端为补充**（不做本地/云端对比实验）。
> 本文记录：部署方式、模型、调用接口、真实测试结果、资源占用、限制与一键启用方法。

## 一、结论

**已在本机部署并实测通过**：文献图片识别（结构化图注）与屏幕截图识别（自然语言问答）
两条路径都跑通，走的是**产品同一条代码路径**，**零改代码**即可切换（只填设置页三格）。

## 二、部署方式（实际执行过的步骤）

| 步骤 | 命令/结果 |
|---|---|
| 1. 安装 Ollama | 先试 `winget install Ollama.Ollama` → **下载停滞 25 分钟 0MB**（卡死），已终止；改**官方安装包直下**：`curl -L https://ollama.com/download/OllamaSetup.exe`（实际 1.46 GB，2.05 MB/s，约 12 分钟）|
| 2. 静默安装 | `OllamaSetup.exe /VERYSILENT /NORESTART /SUPPRESSMSGBOXES` → 装到 `%LOCALAPPDATA%\Programs\Ollama`（用户级，无需管理员）|
| 3. 启动服务 | `ollama serve`（由本会话托管）；另恢复托盘应用 `ollama app.exe` |
| 4. 开机自启 | 写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Ollama = "...\ollama app.exe"`（**由本次部署添加，未询问**；不需要时一条命令即可删除，见文末）|
| 5. 拉模型 | `ollama pull qwen3-vl:4b` → 3.3 GB，成功 |

**版本**：Ollama **0.40.3**（Qwen3-VL 要求 ≥ 0.12.7 ✓）

## 三、模型与调用接口

| 项 | 值 |
|---|---|
| 模型 | **`qwen3-vl:4b`**（3.3 GB；同系列还有 2b/8b/30b/32b，8 GB 显存推荐 4b）|
| 端点 | **`http://127.0.0.1:11434/v1`**（Ollama 的 OpenAI 兼容层）|
| 接口 | `POST /v1/chat/completions`，`content` 为分片数组，图片用 `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` |
| Key | 客户端必须填但**本地服务忽略**（我们填 `ollama`；留空会回退"文献解析 LLM"的 Key，也能用）|
| 与本项目的关系 | 与 `src/literature/vision.py::_chat_vision` 的实现**完全一致**（同样是 OpenAI 兼容 image_url + base64）→ **无需改代码** |

## 四、真实测试结果（`scripts/verify_local_vision.py`，可重复运行）

素材：**安装版用户数据里的真实文献图**（只读引用）+ **本机主屏真实截图**。

| 素材 | 耗时 | 模型输出（摘要） |
|---|---|---|
| 文献图（¹H NMR 谱，59KB PNG）| 5.8s（热态）| 图类型 `spectra`／技术 `NMR`；描述"展示 a-h 标记的化学环境信号峰位置…"；**confidence=medium**，依据"图中未标注具体数值，无法确定" |
| 文献图（SEM/AFM，77KB JPG）| 17.9s | 图类型 `structure`／技术 `AFM`；**数值 最大高度 3.5 nm**；confidence=high，依据"红色箭头标注 3.5 nm" |
| 屏幕截图（212KB PNG，聊天式路径）| 14.9s | 准确描述界面："COF 科研助手／机器学习实验平台"，列出左侧导航项（首页/工具箱/查询打分/…/我的），指出"科研助手"高亮 |

**汇总**：成功 3/3，总 38.6s，**平均 12.9s/张**（冷启动首张约 79s，含模型加载）。
按此速率，**98 张文献图约 21 分钟**（批量识别已支持逐张进度与取消）。

> 诚实边界（模型自己也这么报）：**密集谱图的精确数值不可全信**。NMR 那张它明确说
> "未标注数值，无法确定"并给 medium —— 这正是我们提示词要求的"读不准宁可不写"。
> 要进实验记录/论文的数值仍需人工复核。

## 五、资源占用（实测）

| 项 | 值 |
|---|---|
| 模型驻留 | `ollama ps` → **3.5 GB，100% GPU**，context 4096 |
| 显存占用 | 加载后 **4756 MiB / 8188 MiB**（约 58%）|
| 闲置卸载 | 默认约 **4 分钟**后自动从显存卸载 → 不与 GNN 训练长期抢显存 |

## 六、怎么用（用户侧，两步）

1. 确保 Ollama 在运行（已设开机自启；也可手动 `ollama app.exe`）。
2. **设置 → 文献解析 LLM → 视觉读图** → 点 **「用本机模型」** 按钮（自动填 `qwen3-vl:4b`
   + `http://127.0.0.1:11434/v1` + Key）→ **保存设置**。
   之后：文献图片「AI 识别」、助手「截图提问」、助手 `view_figure` 全部走本机模型；
   想用云端时把端点/Key/模型名改回云端即可（两者共存，随时切换）。

## 七、已知限制

1. **依赖 Ollama 常驻**：服务没起时视觉不可用（设置页状态行会显示"未启用/不可用"，
   接口返回 409 并给中文原因，助手会如实说"看不到图"而不是编造）。
2. **速度**：热态 6–18 秒/张；冷启动首张 10–80 秒。批量 98 张约 21 分钟（可取消）。
3. **显存**：4b 档占 3.5 GB；若同时做 GNN 微调可能显存紧张（闲置会自动卸载）。
4. **质量**：明显弱于云端大模型，尤其是精细数值与专业判读；作为"日常批量预标注 + 离线/隐私场景"主力，关键结论仍建议云端复核或人工确认。
5. 本文的安装/自启/模型拉动均为**本机一次性动作**，不影响仓库代码；打包发版不含 Ollama。
