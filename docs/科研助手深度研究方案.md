## 二、Deep Research 五模块 → 本项目落地映射

用户提出的「感知-规划-行动」五模块与本项目现有基座逐一映射，明确**哪些已有、哪些新建、新建长什么样**：

| Deep Research 模块 | 本项目现状 | 落地形态（新建/复用） |
|---|---|---|
| **Planner 规划** | 隐式（LLM 直接在 loop 里选工具，无显式计划） | 新建「研究计划」步骤：复杂问题先让 LLM 输出 plan JSON（2–5 个子问题 + 每个子问题标注检索源：学术库/本地图谱/联网），前端渲染计划卡，**用户可确认或增删**后再执行。简单问题自动跳过规划（≤1 个子问题即直答） |
| **Executor 执行/检索** | 10 个本地工具，无联网 | 新增工具族：`web_search` / `academic_search`（arXiv+PubMed+Semantic Scholar+Crossref）/ `fetch_page`（网页全文提取）；复用现有 query_graphrag / read_experiment_records / query_dft 作为「本地证据源」 |
| **Critic 反思/验证** | ❌ 无 | 新建两层：①**引用核验器**（规则型，见 §4，防幻觉底线）；②**Reflexion 自我批判轮**（LLM 型：核对「答案是否覆盖计划中的每个子问题、关键论断是否有证据支撑」，发现缺口→追加 ≤1 轮定向检索后重写）。借鉴 Academic Research Assistant 的 CRAG 思想：检索结果明显不相关时先纠正 query 再检索 |
| **Memory 记忆** | 会话 jsonl + 会话压缩 + 全局 memory.md + GraphRAG 本地知识 | 复用为主；补：①按单体组记忆文件（§1.2-#3）；②研究报告落盘（`user_data_root/research/report_*.json`）可回看、可进助手上下文 |
| **Writer 报告生成** | 只有对话回答与方案卡 | 新建「研究报告」产物：标题/摘要/分节正文/**参考文献列表（GB/T 7714 + DOI，复用 records/export_docx 的引用格式化）**；一键导出 docx；可选「保存为实验记录附件/方案卡」 |

**结论：基座（loop/注册表/确认/SSE/记忆/人格）全部复用，真正要新建的是「4 个工具 + 1 个计划步骤 + 1 个核验器 + 1 个研究循环 + 报告落盘」。**

## 三、联网与学术检索能力设计（本次核心）

### 3.1 新工具族（全部遵守现有 `{text,details,is_error}` 契约）

| 工具 | 参数 | 返回 | 数据源 |
|---|---|---|---|
| `web_search` | query, n=5 | 标题+URL+摘要（中文语境直接可读） | 搜索 API provider 抽象：Tavily（默认）/ Serper / SerpAPI；**未配置 key 时工具整体缺席**（list_tool_schemas 动态裁剪），env-status 报告 `search: not_configured` |
| `academic_search` | query, source∈{arxiv, pubmed, semanticscholar, crossref}, n=5 | 标题/作者/年份/期刊/**DOI**/摘要片段 | arXiv API、PubMed E-utilities、Semantic Scholar Graph API（均免费无 key 或可选 key）；Crossref 复用现有 `src/literature/crossref.py` |
| `fetch_page` | url | 正文纯文本（≤30KB 截断） | requests + **trafilatura**（纯 Python 网页正文提取，lxml 已在 PyInstaller 依赖中）。**不引 Playwright/Crawl4AI**（浏览器级太重，桌面后端撑不住；JS 渲染站点抓不到就明说抓不到，让模型换源） |
| `lookup_paper_doi` | doi | 文献元数据（复用现有 literature.lookup + resolver，DOI 直连原文） | 已有能力，注册为工具即可（v1.5.4 的 DOI 基建直接受益） |

### 3.2 选型论证（针对本项目约束）

1. **搜索 API 选型**：Tavily 对 Agent 场景最优（结构化结果、可带内容摘要），但需付费 key 且国内直连稳定性需实测；Serper/SerpAPI 走 Google 需 key。**方案：provider 抽象 + Tavily 首选 + Serper 备选**；免费兜底不承诺（DuckDuckGo 抓取易限流，仅 P0 联调用）。key 存设置页配置（见 3.3），**绝不进包、绝不打日志**。
2. **学术源选型**：arXiv/PubMed/Semantic Scholar **免费且国内可直连**，作为深度研究的默认主力源；Crossref 已在文献录入链路验证可用。Google Scholar 国内不可直连，**不采用**（Serper 的 scholar 端点可作为付费可选项，P2 再说）。
3. **网页抓取选型**：trafilatura（~纯 Python，PyInstaller 友好）；明确不做 Crawl4AI/Playwright（体积、浏览器依赖、维护成本三重否决）。
4. **框架选型（路线一 vs 路线二）**：**选路线二（从零构建）**。理由：①SearchClaw/SciAssistant/Academic-RA 是**独立应用**，无法内嵌进我们的 FastAPI 桌面后端；②我们已有 loop/注册表/确认/SSE/记忆全套基座，LangChain/LangGraph 引入后 PyInstaller 体积与兼容风险大、收益低；③只**借鉴其架构思想**：SearchClaw 的「研究规划 + 质量门禁」、Academic-RA 的「CRAG 自纠错 + Reflexion」。表里对照：

| 借鉴对象 | 借鉴点 | 落地 |
|---|---|---|
| SearchClaw | 研究规划分步执行、质量门禁（结果不达标不产出报告） | §2 Planner + §4 核验器 |
| SciAssistant | 多学术数据库聚合 + 专业报告生成 | §3.1 academic_search + §2 Writer |
| Academic Research Assistant | CRAG（检索→评估→纠正重查）+ Reflexion 反思 | §2 Critic 两层 |

### 3.3 配置与安全

- 设置页新增「联网搜索」区：provider 下拉 + api_key + 总开关（默认关，与离线分发纪律一致）；写入 `llm_settings.local.json`（save_settings 已是读-改-写，互不覆盖）。
- `/api/llm/env-status` 增加 `search: {enabled, provider, configured}` 口径，助手状态页与工具注册表据此动态裁剪。
- 安全红线：fetch_page 拒绝内网/环回 IP 与 file:// 协议；单页 ≤2MB、超时 ≤20s；所有搜索/抓取工具**只读、无需二次确认**。

## 四、引用核验器（Critic 第一层，防幻觉底线）

复用迭代建议的 `normalize_evidence` 口径，新建 `src/assistant/verify.py`：

1. **白名单收集**：本轮全部工具返回的 details 中出现的 CAS 号（正则）、DOI（正则 + resolver 规范化）、URL 域名、文献标题。
2. **回答扫描**：助手最终回答中的每个 CAS / DOI / 文献标题 / 「XX 年 XXX 期刊」样式引用必须命中白名单；
3. **不命中即打回**：loop 内追加一轮「你引用了不在检索结果中的 X，请删除或改述」→ 重写；重写后仍违规 → 在回答中显式标注「该引用未经系统核实」并提示用户（诚实降级，不静默）。
4. 与 v1.5.4 DOI 基建闭环：回答中的 DOI 一律渲染为可点击链接；回答引用的文献可一键「录入文献库」（复用文献录入草稿流程）。

## 五、深度研究入口与交互（前端形态）

- 科研助手页新增「**深度研究**」模式开关（普通对话 / 深度研究两种模式，研究模式可指定「联网」是否允许）。
- `POST /api/assistant/research`（SSE，事件契约在现有 token/tool_* 上扩展）：
  ```
  plan（子问题列表，用户确认/修改）
   → step_start / tool_*（逐子问题检索，复用现有工具事件卡）
   → critic_note（核验与反思轮说明）
   → writing（报告流式生成）
   → report（报告落盘 id + docx 下载链接）→ done
  ```
- 报告保存为 `user_data_root/research/report_*.json`；「我的」页新增「研究报告」列表（查看/导出 docx/删除——删除复用 v1.5.4 迭代建议删除的同款交互）。
- 研究模式不改变现有对话模式：**普通问题仍走轻量 loop，不强制走计划**（避免「杀鸡用牛刀」和 token 浪费）。

## 六、分期实施路线与验收

### P0（约 1 周）：联网搜索工具族 + 引用核验器（普通对话即可问「最新进展」）

- web_search（provider 抽象 + Tavily/Serper）/ academic_search（arXiv+PubMed+Semantic Scholar+Crossref）/ fetch_page（trafilatura）+ 设置页配置 + env-status 扩展
- 引用核验器上 loop（§4）+ 回答内 DOI 可点击
- 验收：问「COF 气体分离最新进展（2025-2026）」→ 助手调 academic_search 返回**带 DOI 的真实文献**并逐条可点开；断网/未配 key 时优雅降级为「联网搜索未配置」提示；回答中编造的引用被核验器拦下。

### P1（约 1 周）：深度研究循环 + 报告生成

- 计划步骤（plan 卡 + 用户确认）+ 逐子问题执行 + Reflexion 批判轮（含 CRAG 纠错重查）
- Writer 报告生成（GB/T 7714 + DOI 参考文献）+ 落盘/导出 docx + 「我的」页研究报告列表
- 顺手补齐 get_monomer_props / cas_resolve / lookup_paper_doi 三工具
- 验收：输入「总结 COF 成膜领域近两年进展，并与我库里 TAPT 组的历史实验对比，给出下步研究方向」→ 完整走 plan→检索（学术库+本地图谱+实验记录）→批判→**带 10+ 条真实 DOI 引用的结构化报告**，可导出 Word；每个论断可回溯到工具结果。

### P2（可选，约 0.5–1 周）：SKILLS + 记忆按组隔离 + 主动研究

- SKILLS 机制：迭代方法论/文献检索 SOP 写成 SKILL.md（frontmatter 进元数据，正文进 system），改 md 即改行为
- 记忆按单体组隔离文件（§1.2-#3）；nudges 扩展「新失误记录 → 建议回顾/深度研究」
- 验收：改一份 SKILL.md 不部署代码即可让助手按新方法论回答；跨天问同一单体组能调出该组专属记忆。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 国内网络：Tavily/Serper/Google Scholar 可达性 | 学术源默认用可直连的 arXiv/PubMed/SemanticScholar/Crossref；搜索 provider 可切换；全部 API 超时 20s + 失败转 toolError 让 LLM 换路 |
| API key 管理 | 只落 `llm_settings.local.json`（本地用户目录），不打包、不打印、不进会话落盘 |
| token 成本（搜索结果长） | 工具返回 text ≤4000 字符（registry 现有 `_MAX_TEXT` 口径）；检索摘要化；研究循环有总预算（默认 8 次检索） |
| 幻觉/编造引用 | 引用核验器打回 + 诚实降级标注（§4）+ domain_rules 红线 |
| PyInstaller 体积与兼容 | 只加 trafilatura（纯 Python，lxml 已在包内）；明确不引 Playwright/Crawl4AI/LangChain |
| 研究循环跑飞（无限检索） | 循环上限：计划 ≤5 子问题 × 每子问题 ≤2 次检索 + 反思轮 ≤1 次重查；超限按现有证据收尾出报告 |
