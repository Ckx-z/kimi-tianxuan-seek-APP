# 发版守卫补充：冻结失败不得继续打包（v1.9.8 实测事故）

## 事故经过（2026-09-20，第 58 轮）

一条"串联式"命令同时做了：清缓存 → PyInstaller 冻结 → 一致性核对 → 双自证 → electron-builder → 打 zip。
结果 **PyInstaller 退出码 = 1**（环境层瞬时故障，见下），但脚本继续往下跑：

- 一致性核对与双自证**全部被跳过**（输出为空，我一开始没注意）
- **electron-builder 仍成功**，用残缺目录打出一个 **141.8 MB** 的安装包（正常 **464 MB**）
- zip **照常生成且"MD5 一致"** —— 校验的是**那个坏包**
- 若照此上传，用户会拿到一个装不上/装完没有后端的安装包

**处置**：立刻删除坏 exe/zip/latest.yml → 重试冻结（成功）→ 完整重跑 → 体量 464.3 MB，双自证 9/9 + 12/12，
zip MD5 一致。已加入体量守卫（`< 300 MB 即拒绝打 zip`）。

## 失败原因（环境层，非项目代码）

```
PyInstaller\utils\hooks\conda.py:367  fnmatch.fnmatch(str(file.parent), str(prefix))
TypeError: str() argument 'errors' must be str, not list
```
PyInstaller 扫描 Anaconda 发行包元数据时崩溃。**同一命令此前多次成功** → 判定为瞬时故障；
**重试即通过**。遇到它不要改项目代码，先重试一次并确认产物体量。

## 强制守卫（今后每次发版都要过）

1. **冻结后立刻检查退出码**，非 0 就**停止**，不允许继续打包：
   ```powershell
   py -m PyInstaller scripts/cof-backend.spec --distpath dist-backend --noconfirm
   if ($LASTEXITCODE -ne 0) { throw "冻结失败，停止发版" }
   ```
2. **存在性 + 体量守卫**（缺一不可）：
   ```powershell
   if (-not (Test-Path "dist-backend\cof-backend\cof-backend.exe")) { throw "冻结产物缺失" }
   ```
   安装包体量 **< 300 MB 视为异常**（正常约 464 MB）→ 拒绝打 zip、拒绝上传。
3. **一致性核对与双自证必须打印结果**；任何一项为空/失败即中止。
   - 前端文件数与 `index.html` MD5 一致；`assets/pdf.worker*` 必须在包内
   - 标准自证 9/9、专项自证 12/12
   - 包内 `data/paper_titles.json` 条数 = 1711（见 checklist §0b）
4. **不要把冻结与打包串成一条不设守卫的命令**——这正是本次险情的成因。
