## 三、DFT 计算模块（核心新功能）

### 3.1 功能定义

输入两个 COF 单体（SMILES / CAS / 从历史或收藏选取），计算**单体间结合能**等基础量化指标，辅助判断缩合反应倾向。

**输出指标（第一期）**：
- 结合能 E_bind = E_复合物 − E_单体A − E_单体B（kcal/mol 与 kJ/mol）
- 各单体量级描述：偶极矩、HOMO/LUMO 能隙（xTB 直接给出）
- 优化后复合物 3D 结构（可交互查看）

**界面要求（与查询打对齐）**：
- 展示每种单体的性质卡（复用 LLM 性质卡组件）✅ 已有
- 单体结构图 + 缩合后二聚体结构图（复用现有结构图管线）✅ 已有
- 计算结果可**收藏**、有**历史计算记录**（复用 prediction_log 模式新建 dft_log）

### 3.2 技术选型（已调研 GitHub）

| 候选 | 仓库 | 结论 |
|---|---|---|
| **GFN2-xTB（首选）** | [grimme-lab/xtb](https://github.com/grimme-lab/xtb)（835★，2026-08 仍活跃） | 半经验紧束缚，单分子优化秒级~分钟级；conda-forge **有 win-64 包**（6.7.1）；官方 Release 也有 Windows 二进制；LGPL-3.0（动态链接二进制可随闭源/开源应用分发） |
| GFN-FF 力场（极速档） | 同上（xtb 内置） | 秒出结果，做"快速预估"档位；文献报道结合能 MAE≈2 kcal/mol，适合相对比较 |
| tblite | [tblite/tblite](https://github.com/tblite/tblite)（216★） | 纯库形态更干净，Python 绑定可用，作为备选/二期替换 |
| xtb-python | [grimme-lab/xtb-python](https://github.com/grimme-lab/xtb-python)（129★） | Python API；但 Windows 下打包复杂，一期用"二进制子进程"更稳 |
| 真 DFT（Gaussian/ORCA/Psi4） | — | ❌ 不嵌入：商用授权/体积/算力都不适合桌面分发；模块预留"导出 Gaussian/ORCA 输入文件"按钮，让用户去超算算高精度 |

**选型结论**：捆绑 **xtb Windows 二进制**（约 90MB，conda-forge win-64 包提取），后端子进程调用。安装包体积 357MB → 约 450MB，可接受；或做"首次使用时一键下载"（二期再议）。

### 3.3 计算管线（后端）

```
SMILES → RDKit ETKDG 3D 构象 → UFF 预优化（RDKit 内置，已随包）
       → xtb --opt（GFN-FF 或 GFN2-xTB 几何优化，xyz 输出）
       → 复合物构造：两单体反应位点对齐初猜（复用产物骨架代码的缩合位点逻辑）
       → xtb 单点 ×3（复合物、单体A、单体B）→ E_bind
```

- **异步任务**：后端任务队列 + 前端轮询/SSE 进度（计算 10s~3min，不能阻塞请求）；复用科研助手 SSE 基建
- **缓存**：以"单体对 SMILES 规范化 + 方法档位"为 key 缓存结果（`user_data_root()/dft_cache/`），重复组合秒回
- **红线文案**：界面固定提示"半经验方法结果仅供相对比较，精确能量请导出输入文件用 DFT 复算"（学术诚信底线）
- **超纲元素处理**：xTB 覆盖到 Z=86，我们的单体池没问题；遇到不支持元素给中文报错

### 3.4 风险与降级

| 风险 | 对策 |
|---|---|
| xtb 二进制分发合规 | LGPL-3.0：以独立二进制 + 提供源码链接方式分发，合规 |
| 个别组合优化不收敛 | 超时（默认 5min）+ 最大步数限制；失败返回部分结果（单点能仍可用）并中文说明 |
| 打包体积 +90MB | 一期直接捆绑；二期可选"按需下载" |
| 复合物初猜不合理导致结合能失真 | 提供 2-3 个初猜取向取最低能；结果页提示"建议结合构象检查" |

## 四、收藏夹体系重构（「我的」模块改版）

### 4.1 数据模型

```
收藏夹 Folder { id, name, created_at }           ← 新实体，可创建/改名/删除（删除两次确认）
收藏 Favorite {
  id, folder_id（默认"收藏夹1"）, monomer_a, monomer_b,
  score_snapshot?   （打分快照，可空）              ← 只有打分
  dft_snapshot?     （DFT 结果快照，可空）          ← 只有 DFT
  两者都有 = 完整收藏                                ← 交叉合并
}
```

- **迁移**：现有收藏全部归入自动创建的「收藏夹1」，无感升级
- **删除收藏夹**：第一次确认 → 第二次输入/点确认；夹内收藏随之删除（UI 明确列出将删 N 条）
- **交叉合并**：查询打分页收藏时，若已有同单体对的 DFT 收藏 → 提示"已存在该组合的 DFT 收藏，是否合并？"，合并后一条收藏带双快照；DFT 页收藏时反之亦然
- **DFT 收藏同打分收藏一样关联实验记录**（实验记录模块的关联选择器把两类收藏都列出）

### 4.2 「我的」页面新结构

```
我的
├── 收藏夹列表（侧栏/页签）：收藏夹1（默认）、+ 新建收藏夹
│     └── 每个收藏夹内：单体组合卡片（打分徽章 / DFT 徽章 / 双徽章）
├── 方案库（含模板管理，已修）
└── （预留）更多资产
```
