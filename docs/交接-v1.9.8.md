## 3. 发布步骤（只需用户一句「发 v1.9.8」）

产物已就绪：`webapp/release/cof-film-recommend-setup-1.9.8.exe`（464.2 MB）、
`COF-Assistant-Setup-1.9.8-win-x64.zip`（464.1 MB，解压 MD5 与 exe 一致）、`latest.yml`。

```powershell
# 1) 打 tag 并推送
git tag -a v1.9.8 -m "COF 科研助手 v1.9.8" ; git push origin master ; git push origin v1.9.8
# 2) 创建 Release（正文见 build/release_body_v197.json 的同类文件，改标题/正文即可）

# 3) 按序上传三资产（exe → zip → latest.yml 最后），再校验 3/3
$env:RELEASE_ID="<新 id>"
py .tmp_xtb/upload_asset.py "webapp/release/cof-film-recommend-setup-1.9.8.exe" "cof-film-recommend-setup-1.9.8.exe" "application/octet-stream"
py .tmp_xtb/upload_asset.py "webapp/release/COF-Assistant-Setup-1.9.8-win-x64.zip" "COF-Assistant-Setup-1.9.8-win-x64.zip" "application/zip"

py .tmp_xtb/verify_release.py <新 id>

Start-Process "webapp/release/cof-film-recommend-setup-1.9.8.exe" -Verb RunAs
```

## 4. 已知问题 / 注意事项

| 项 | 说明 |
|---|---|
| 后端改动需重启进程 | dev 环境无 `--reload`；改完后端**必须重启**再验证（已两次踩坑：405 / 排序不生效） |
| 冻结产物 = HEAD | 每次改 `src/` 或 `api/` 后需重新冻结 + 重打包，否则包内代码落后于仓库 |
| 内联 PowerShell + Python | 引号/中文极易出错 → **一律写成 `.tmp_xtb/*.py` 脚本再跑** |
| 大批量验证会写真实数据 | 所有走 HTTP 的验证都要 `COF_DATA_DIR` 指向临时目录，并在发版前跑 §0b 检查 |
| `resolver` 读取缓存 | 测试里用 `COF_DATA_DIR` 隔离后读写一致；生产无影响 |
